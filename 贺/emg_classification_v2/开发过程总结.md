# EMG 隐藏测试集批量预测 — 问题与解决过程

## 一、从单文件预测到批量预测

### 发现问题

原始预测函数 `emg_predict_two_stage.m` 设计为接收单个文件路径，输出该文件的预测标签。但隐藏测试集包含 36 个去标签化的 `.mat` 文件（`1.mat` ~ `36.mat`），需要逐个预测并按照助教给出的 CSV 模板汇总提交。

### 解决思路

新建 `emg_predict_batch.m`，核心流程：

1. **模型只加载一次**：将 `load(model_file)` 放在循环外，避免 36 次重复加载
2. **遍历并排序**：用 `dir` 获取所有 `.mat` 文件，从文件名解析出数字 ID 并升序排列，确保输出顺序与模板一致
3. **逐文件预测**：对每个文件执行完整的「预处理 → 分段 → 特征提取 → 两阶段分类 → 多数投票」流程
4. **输出 CSV**：用 `table` + `writetable` 生成 `Pred_Labels_Group09_Submit1.csv`，表头为 `ID, Pred_Label`，严格匹配模板格式

### 关键细节

- 模型文件路径指向嵌套目录 `emg_classification_v2/models/two_stage_model_v2.mat`，需要确认路径正确
- 标签映射与 Data_Specification 一致：1=哑铃弯举，2=垂式弯举，3=推肩

## 二、动作段检测分段过多问题

### 发现问题

助教明确说明每个测试文件包含 4~6 次重复动作，但运行批量预测后发现很多文件检测出了 20+ 个动作段。分段过多会导致：
- 每段信号太短，特征提取不可靠
- 噪声段被当作动作段参与投票，拉低预测准确率

### 分析原因

写了一个诊断脚本 `emg_segment_diagnose.m`，对单个测试文件可视化信号波形、能量包络、阈值线和检测到的段。观察发现：

- **85% 百分位阈值偏低**：能量曲线在两个重复动作之间的"休息"区间并未降到很低，85% 分位数恰好切在这些过渡区间内，导致一次动作的短暂回落被识别为"不活跃"，一个动作被切成多段
- **合并间隔太小**：原代码 `min_gap = 3`（3 个窗口，即 0.15 秒），两次动作内的短暂回落若超过 0.15 秒就不会被合并

### 尝试与迭代

| 尝试 | 改动 | 结果 |
|------|------|------|
| 只增大 min_gap 到 30（1.5秒） | 靠时间间隔合并相邻段 | 单个文件能到 6 段，但不同人动作节奏不同，硬编码时间不可靠 |
| 完全重写分段函数 | 基线噪声估计 + 形态学闭运算 | 很多文件检测到 0 段，阈值过高 |
| **最终方案** | min_gap 适度（0.5秒）+ 能量筛选 | 段数稳定在 5-6 |

### 最终方案

```
min_gap = 10（约0.5秒）
if 检测到的段数 > 6:
    计算每段的平均能量
    按能量降序排列
    只保留最强的6段
```

**核心思想**：不依赖时间经验值来决定段数，而是利用信号本身的能量特征——真正的动作段能量远高于噪声碎片，按能量排序取 top-6 即可过滤掉虚假段。

### 为什么这个方案更鲁棒

- `min_gap = 0.5秒` 只负责合并极短的碎片（明显属于同一次动作），不参与段数控制
- 段数由能量筛选决定，与具体的动作节奏、休息时长无关
- 上限设为 6 与助教给出的"4-6 次重复"一致，即使偶尔只检测到 4-5 段也不会被强制凑到 6 段
