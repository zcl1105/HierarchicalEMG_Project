## 一、动作检测与分割

### 1.1 问题背景

原始 EMG 数据是连续长时记录（每文件 40-50 秒），包含 4-6 次重复动作和间歇休息。需要从中切出有效动作窗口用于特征提取。

**核心难点**：四个批次的数据采集条件不同，电极增益差异巨大：

| 批次 | CH1 典型 RMS | CH2 典型 RMS | 动态范围 |
|------|-------------|-------------|---------|
| 数据二 | ~25k | ~30k | 1.1x-1.5x |
| 数据三 | ~150k | ~130k | 1.2x-1.7x |
| 数据四 | ~420k | ~34k | 1.2x-1.5x |

数据四中 CH1 可达 CH2 的 **100 倍**，如果直接用 `sqrt(rms1² + rms2²)` 合并能量，CH2（肱三头肌）的贡献几乎为零，推肩动作的窗口检测完全失败。

### 1.2 解决方案：通道归一化自适应阈值

**完整流水线**：

```
原始EMG → 滑动RMS → P95归一化 → 合并能量 → 平滑
→ 自适应阈值 → 填小间隙 → 滤短片段 → 前后填充
→ 合并重叠 → 合并双峰 → Top-6能量筛选 → 输出窗口
```

### 1.3 核心创新：P95 通道归一化

**原理**：各通道 RMS 除以自身第 95 百分位数，消除绝对幅值差异。

```matlab
% segment_actions.m 第30-36行
% --- 通道归一化能量 ---
p95_1 = prctile(rms1, 95);        % CH1 的 P95 归一化基准
p95_2 = prctile(rms2, 95);        % CH2 的 P95 归一化基准
rms1Norm = rms1 / max(p95_1, eps); % CH1 归一化到 [0, ~1] 区间
rms2Norm = rms2 / max(p95_2, eps); % CH2 同理
energy = sqrt(rms1Norm.^2 + rms2Norm.^2);  % 等权合并
```

**为什么用 P95 而不是最大值**：P95 对尖峰伪迹鲁棒——单个运动尖峰不会把它拉偏，而最大值会被伪迹严重影响。

**为什么用 P95 而不是中位数**：中位数代表静息基线，P95 代表激活水平。用 P95 归一化后，静息时两通道都接近 0，激活时上升到 ~1.0，能量曲线的"安静 vs 激活"对比度最大。

**数值对比**：

| | 归一化前 | 归一化后 |
|------|---------|---------|
| CH1 激活值 | 420,000 | 0.90 |
| CH2 激活值 | 34,000 | 0.85 |
| CH2 在能量中占比 | **0.5%** | **48%** |

### 1.4 自适应阈值

```matlab
% segment_actions.m 第38-45行
smoothFrames = max(3, round(cfg.energySmooth_s * cfg.fs / stepLen));
energySmooth = movmean(energy, smoothFrames);     % 平滑能量曲线

baseLevel = median(energySmooth);                  % 静息基线（中位数）
activeLevel = prctile(energySmooth, 95);           % 激活水平（P95）
dynamicRange = activeLevel - baseLevel;             % 动态范围
threshold = baseLevel + cfg.thresholdRatio * dynamicRange;  % 自适应阈值
```

**自适应公式**：`阈值 = 中位数 + 0.20 × 动态范围`

- 不需要手动设定绝对阈值
- 每文件独立计算，不受批间幅值差异影响
- `thresholdRatio=0.20` 意味着阈值在基线和峰值的 20% 处

### 1.5 Top-6 能量筛选

**问题**：参数调优无法同时处理所有边界情况——同一动作内的短暂 RMS 回落（需填小间隙）和真正的动作间休息（需保留边界）之间没有清晰界限。

**解决方案**：不依赖时间参数控制段数，而是利用信号本身的能量特征。多于 6 段时，计算每段的合并通道 RMS 能量，按能量降序只保留最强 6 段。

```matlab
% segment_actions.m 第96-107行
if size(segments, 1) > 6
    segEnergy = zeros(size(segments, 1), 1);
    for i = 1:size(segments, 1)
        % 每段的能量 = 两通道 RMS 之和
        segEnergy(i) = sqrt(mean(emg1(segments(i,1):segments(i,2)).^2)) ...
                     + sqrt(mean(emg2(segments(i,1):segments(i,2)).^2));
    end
    [~, sortIdx] = sort(segEnergy, 'descend');  % 按能量降序
    keep = sort(sortIdx(1:6));                   % 取前6个，保持时间顺序
    segments = segments(keep, :);
end
```

**为什么有效**：真实的动作段（肌肉发力）能量远高于噪声碎片。按能量排序取 Top-6，自然过滤掉了阈值误检的虚假段。

**效果**：

| | 优化前 | 优化后 |
|------|--------|--------|
| 单文件平均段数 | 15-25 | **5-6** |
| 策略 | 纯阈值切割 | 阈值 + Top-6 筛选 |
| 对不同节奏的适应 | 差（硬编码时间） | 好（自适应能量） |

### 1.6 答辩可能问到的点

- **Q: 为什么是 Top-6 而不是 Top-5 或 Top-7？** → 数据标注规范约定每文件 4-6 次重复动作，6 是上限。如果某文件只有 4 次有效动作却设成 Top-7，会引入一个噪声段。
- **Q: 如果某文件能量最强的 6 段里有噪声段怎么办？** → 噪声段的绝对能量远低于真实动作段（通常差一个数量级），排序天然排在最后。加上 `minDuration_s=0.35s` 在之前已经过滤了短噪声。

## 二、参数调优

### 2.1 参数体系

| 参数 | 最终值 | 作用 | 调优逻辑 |
|------|--------|------|----------|
| `rmsWindow_s` | 0.15s | 滑动窗宽 | 平衡平滑和时间分辨率 |
| `energySmooth_s` | 0.12s | 能量平滑 | 0.08→0.12，低动态范围文件需更长平滑 |
| `thresholdRatio` | 0.20 | 阈值比例 | 0.30→0.20，检出弱激活（尤其推肩） |
| `minGap_s` | 0.20s | 填小间隙 | 0.10→0.20，避免碎片化 |
| `minDuration_s` | 0.35s | 最短时长 | 0.40→0.35，保留短促动作 |
| `sameActionGap_s` | 0.75s | 双峰合并 | 0.90→0.75，避免误合并相邻动作 |

### 2.2 调优方法

1. **分批次分析**：用 Python 加载 51 个训练文件，统计每文件的幅值范围、动态范围、RMS 分布
2. **单文件诊断**：打开 `showTrainPlots=true`，逐个检查分割诊断图的窗口位置和阈值线
3. **迭代验证**：改一个参数 → 跑全量 → 看隐藏测试集结果和 CV 准确率

### 2.3 答辩可能问到的点

- **Q: 这些参数值是怎么确定的？** → 不是一次调出来的。先做数据统计分析了解幅值分布，然后在单文件上可视化验证，最后在全部训练集上迭代对比。
- **Q: 换一批数据需要重新调吗？** → 核心设计（P95 归一化、自适应阈值、Top-6 筛选）都是数据自适应的，不依赖绝对幅值。但 `thresholdRatio` 和窗口参数可能需要微调。

## 三、文件级决策机制

### 3.1 问题背景

每个 .mat 文件经分割后得到 N 个动作片段（N=4-6），每个片段经过两层分类器独立预测。需要将 N 个片段的预测汇总为**一个**文件级标签。

### 3.2 从简单投票到置信度仲裁的演进

**第一阶段：简单多数投票（mode）**

```matlab
overallLabel = mode(hiddenPred);  % 哪个标签出现最多就用哪个
```

**问题**：当票数接近时（如 3:2），2 个错误的低置信度预测就能翻转最终结果。

**第二阶段：平均特征向量（被放弃）**

取所有片段的特征均值，对平均向量做一次预测。

**问题**：异常片段（分割不准导致特征极端）会拉偏平均值。

**第三阶段：多数投票 + RF 置信度仲裁（当前方案）**

### 3.3 当前决策逻辑

```matlab
% aggregate_file_prediction.m 核心逻辑（第20-49行）

% 步骤1: 统计各标签票数
voteCounts = zeros(1, 3);
for c = 1:3
    voteCounts(c) = sum(predLabels == c);
end

[~, majorityLabel] = max(voteCounts);          % 多数标签
curlMargin = abs(voteCounts(1) - voteCounts(2)); % 弯举票差

% 步骤2: 计算弯举类片段的 RF 平均分类分数
curlIdx = stage1Pred == 0 & predLabels <= 2;   % 非推肩且非3标签
if any(curlIdx)
    curlScores = stage2Scores(curlIdx, :);
    meanScore1 = mean(curlScores(:, 1), 'omitnan'); % BicepsCurl 平均分
    meanScore2 = mean(curlScores(:, 2), 'omitnan'); % HammerCurl 平均分
end

% 步骤3: 决策
if majorityLabel <= 2 && curlMargin < cfg.fileVoteMinMargin
    % 弯举票差太小 → 用 RF 分数仲裁
    if meanScore1 > meanScore2
        fileLabel = 1;  % BicepsCurl
    else
        fileLabel = 2;  % HammerCurl
    end
else
    % 票差足够 → 信多数投票
    fileLabel = majorityLabel;
end
```

### 3.4 仲裁实例

**文件 22.mat（5 个片段）**：

```
片段预测: [BicepsCurl, BicepsCurl, HammerCurl, HammerCurl, HammerCurl]
票数统计: BicepsCurl=2, HammerCurl=3, ShoulderPress=0
弯举票差: |2-3| = 1 < 2(阈值) → 触发仲裁

RF 平均分数:
  BicepsCurl 两票: [0.90, 0.88] → 平均 0.89  (RF 很确信)
  HammerCurl 三票: [0.51, 0.52, 0.53] → 平均 0.52  (RF 几乎瞎蒙)

  0.89 > 0.52 → 翻盘判为 BicepsCurl
```

**为什么这样设计**：

- 票数只看"谁赢了"，不关心"赢了多少"。3 个不自信的 HammerCurl（51% 概率）加起来的分量不如 2 个很自信的 BicepsCurl（90% 概率）。
- RF 分数反映的是 100 棵树中投票给该类的比例，比单一的离散标签包含更多信息。

### 3.5 效果统计

| 决策规则 | 触发次数 | 占比 |
|----------|---------|------|
| majority_vote（多数投票） | 32/36 | 89% |
| stage2_score_tiebreak（仲裁） | 4/36 | 11% |

86% 的文件可以通过多数投票直接确定，仲裁只在票差 ≤1 时作为安全网介入。

### 3.6 答辩可能问到的点

- **Q: 为什么不用所有片段的平均 RF 分数，而要混合投票和分数？** → 投票对异常片段鲁棒——一个分割错的片段投了错票，但其他 5 个对票能盖过去。平均分数相反，一个极端片段会拉偏所有。投票是主力，分数是保镖。
- **Q: `fileVoteMinMargin=2` 为什么不是 1 或 3？** → 设为 1 等于永不仲裁（1 票差即判定），失去仲裁意义。设为 3 则仲裁太频繁，投票机制被架空。且训练文件片段数 4-6，2 票差约占总段数的 1/3-1/2，判断合理。
- **Q: 如果推肩类的票差也很小怎么办？** → 推肩由 Stage 1（SVM）判断，与弯举分类独立。实际中推肩检测准确率 93.4%，基本不需要仲裁。
